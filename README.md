# Траты Сани

Настольное приложение для Windows (Electron + React + SQLite) для учёта расходов, внесений, остатка денег и формирования отчётов за период.

Валюта: **тенге (₸, KZT)**.

## Установка на другой компьютер

Готовый установщик: **`release\Траты Сани Setup 1.0.0.exe`**

Установщик уже содержит подготовленную базу данных с категориями — при первом запуске на новом компьютере она автоматически разворачивается в `%APPDATA%\Траты Сани\database\expenses.db`. Устанавливать Node.js на целевой компьютер **не нужно**.

## macOS (Apple Silicon)

Готовый `.dmg` собирается в облаке GitHub Actions — Mac не нужен:

1. Загрузить репозиторий на GitHub
2. Открыть **Actions → Build macOS (arm64) → Run workflow**
3. Скачать артефакт `Traty-Sani-mac-arm64` (файл `.dmg`)

Если есть свой Mac — то же самое выполняется локально:

```bash
npm run build:mac      # electron-builder --mac --arm64
```

Результат: `release\Траты Сани 1.0.0 arm64.dmg`

**Ограничения macOS-версии**

- Собирать `.dmg` можно **только на macOS** — electron-builder использует системные утилиты macOS для создания образа. С Windows это не работает, поэтому Windows-сборка и macOS-сборка выполняются разными командами
- Собранный образ **не подписан**: при первом запуске macOS покажет предупреждение «Приложение не отозвано разработчиком». Открыть: правый клик по `.app` → «Открыть» → «Открыть». Или в «Системных настройках → Конфиденциальность и безопасность» нажать «Открыть всё равно»
- Подпись и нотарификация (чтобы предупреждения не было вовсе) требуют Apple Developer Account и платного пения GitHub Actions
- Собран только под Apple Silicon (M1/M2/M3/M4). Для Intel добавьте `--x64` в `build:mac` и `x64` в `mac.target`

**Платформенные различия в оформлении окна**

На macOS системные кнопки окна находятся слева, а не справа, поэтому используется `titleBarStyle: 'hiddenInset'` с индивидуальным положением кнопок, а заголовок сдвинут вправо. Логика приложения, база и отчёты на обеих платформах идентичны.

## Возможности

**Категории и подкатегории**
- **Закуп** — подкатегории: Российский, Рыба, Боксы, Курица, Овощи, Хоз.товары, Кола, Вода, Камшат
- **Такси**
- Любые свои категории и подкатегории добавляются через «Управление категориями» и сохраняются в БД

**Траты**
- Добавление траты: категория, подкатегория, сумма, дата, комментарий
- Удаление трат, фильтрация по периоду
- Итоговая сумма за выбранный период

**Внесение денег**
- Кнопка «Внесение» — операция поступления денег (отличается от «Указать остаток», который фиксирует снимок текущего состояния)
- **Комментарий обязателен.** Ошибку нельзя обойти: кнопка неактивна без комментария, проверка дублируется в главном процессе и на уровне БД (`CHECK (length(trim(note)) > 0)`)
- Отдельная вкладка «Внесения» со списком операций и итогом
- Внесения учитываются в отчёте за период

**Остаток**
- Кнопка «Указать остаток» фиксирует базовую сумму на конкретную дату (сверка с банком)
- **Текущий остаток производный**: последняя отметка + все внесения после неё − все траты после неё. Внесение сразу отражается в остатке
- Если отметок нет, остаток считается от нуля по всем операциям
- Порядок операций в пределах одного дня определяется временем ввода, поэтому внесение, сделанное после отметки в тот же день, учитывается

**Отчёт за период (макрос)**
- Кнопка «Отчёт» формирует сводку:
  - **начало (база)** периода
  - сумма **внесений**
  - сумма **трат**
  - **на выходе** — деньги после всех внесений и вычетов
  - разбивка по категориям и подкатегориям, список внесений
- Формула: `на выходе = начало (база) + внесения − траты`
- Если отметка «Указать остаток» попадает внутрь периода, она становится базой периода: операции до неё уже учтены в её сумме и повторно не считаются
- Экспорт отчёта в CSV

**Периоды**
- Быстрые пресеты: День, Неделя, Месяц, Квартал, Год
- Произвольный выбор дат вручную

## Установка

Готовый установщик: `release\Траты Сани Setup 1.0.0.exe`

Данные хранятся в `%APPDATA%\Траты Сани\database\expenses.db`

## Разработка

Требуется Node.js 20 (LTS).

```bash
npm install
npm run dev                # запуск в режиме разработки
npm run typecheck          # проверка типов
npm run build              # сборка renderer + main
npm run build:template-db  # генерация resources/template/expenses.db
npm run build:win          # сборка установщика .exe для Windows (включая базу)
npm run build:portable     # portable-версия .exe для Windows (без установки)
npm run build:mac          # сборка .dmg для macOS (arm64) — только на macOS
```

### Портирование на iOS / Android

Логика вынесена в слои, которые переиспользуются:
- `src/renderer/types.ts` — модели данных
- `src/renderer/lib/format.ts` — форматирование и периоды (без зависимостей от DOM/Node)
- `src/main/schema.ts` — схема БД и дефолтные категории
- `src/main/main.ts` — SQL-запросы остатка и отчёта (переносятся в мобильную БД как есть)
- `src/renderer/components/` — React-компоненты

Для мобильной версии заменяется только транспортный слой (`window.electronAPI` → HTTP/React Native SQLite), компоненты и логика отчётов остаются прежними.

### Как база попадает в установщик

1. `npm run build:template-db` генерирует `resources/template/expenses.db` — пустую БД со схемой и дефолтными категориями. Скрипт запускается под Electron, т.к. `better-sqlite3` собран под ABI Electron.
2. Схема и дефолтные категории берутся из `src/main/schema.ts` — это единый источник истины для рантайма и генератора шаблона.
3. electron-builder кладёт базу в `resources/template/` внутри приложения (`extraResources`).
4. При первом запуске `main.ts` копирует шаблон в `%APPDATA%`, если БД ещё не существует.
5. `applySchema()` вызывается при каждом старте и идемпотентна: обновляет структуру, но не трогает пользовательские данные.
